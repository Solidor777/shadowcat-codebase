# Token-attached regions, portals, placed regions, template conversion

Region features beyond the base trigger/field model. Read it before changing region anchors, portal offers, module placements or the template-to-region conversion.

## Token-attached (anchored) regions

- `RegionEngine.anchor` is `RegionAnchor {token, include_carrier, follow_rotation}` (`deny_unknown_fields`). `regions::anchored_parts` computes the translated geometry: a rect translates, a rotated rect becomes a polygon, a circle's centre rotates (clockwise, y down), non-finite input fails closed.
- `SceneEcs::anchored_region_parts` (in `scene::anchored_regions`) is the SINGLE entry every consumer calls: `region_field_if`, `build_trigger_region` and `region_occluder_entries` all read it. A region is dormant (no geometry, no effect) when its carrier is missing, is not a token, or is on another scene. Never read a region's stored geometry directly for anything that acts on it.
- Mover exemption: `region_field` / `trigger_regions` take the mover and exempt it from an anchored region unless `include_carrier`; `RouteMover.token` carries it, and `move_exec` passes `Some(token)`.
- Cache invariant: a new geometry input enters a cache snapshot as its RESOLVED value, never as a separate key. `LightingInputsSnapshot` and `VisibilityInputsSnapshot` already hold the resolved ambient maps and wall entries read through `anchored_region_parts`, so a carrier move misses the cache by construction; `scene::tests::anchored_lighting_cache` pins it. A separate carrier-pose key would fork the decision.
- Triggers: `Room::fire_attached_region_triggers` runs after the `execute_move` fire, after each `fire_placement_triggers` report (placement, GM teleport, GM drag) and after a post-teleport re-fire (with `allow_teleport` false, so no chain). `SceneEcs::attached_occupants` / `AttachedOccupant` use the token's CENTRE cell; `attached_regions_of` is the cheap guard (empty when nothing follows the carrier). `TriggerReport.enter_only` limits a named-region pass to Enter/Arrest; Exit is never filtered. The carrier is not its own occupant.
- Client twin: `scene-docs` `anchoredRegionGeometry` / `offsetRegionGeometry` / `carrierPoseFor` / `resolveRegionGeometry` / `reanchorRegion` mirror `anchored_parts` (a parity test pins the server rotation fixture). `RegionView` resolves geometry per frame, `livePose` + `tick()` ride the token animation, and an unresolved anchored region yields no shape from `regionShapeSpec`. `topRegionAt(regions, p, store)` takes the document store to resolve anchors. A hidden carrier hides its aura visually.
- Authoring: the `ToolRail` region editor writes the anchor through `ToolController.setRegionAnchor` (one Update); `DormantRegionList` lists regions whose `carrierPoseFor` is null (the single dormancy rule), offers Edit, Follow selected token (enabled only for exactly one valid carrier) and Delete (full pre-image), and mounts inside the GM region controls. A dormant region cannot be picked on the canvas, so this list is the only way to re-attach or delete it.

## Portals

- `TriggerEffect::Teleport` and `TriggerEffect::PortalChoice {prompt, options}` (`PortalOption {label, target, reveal_scene}`, bounded by `MAX_PORTAL_OPTIONS` and `MAX_PORTAL_LABEL_CHARS`). `Room::apply_teleport_to(TeleportSubject)` is the SINGLE teleport routine: a trigger teleport, an accepted portal choice and a GM placement all go through it. Under `allow_teleport` false a `PortalChoice` is refused like a chained teleport.
- Offers: `ws::room::portal` (`offer_portal`, `handle_choose_portal`, `handle_open_portal`) registers a `PortalOffer` only when `allow_teleport` holds, in `Room.portal_offers` (a std Mutex, never held across an await, writers under the publish guard). The wire carries option labels and indices, never coordinates; `destination_name` only with `reveal_scene`; the offer expires after a TTL. Refusals are one uniform text (a GM variant adds detail); a stranger cannot burn another user's offer; a secret region's offer is GM-only. An accepted choice fires a synthetic Teleport through `apply_teleport_to`; an Exit event creates no offer. Session pause blocks ChoosePortal acceptance only; decline and open stay allowed.
- Egress: `portal_offer_admitted` filters the per-recipient broadcast (`broadcast_aux`). Client: `AppContext.portal` seam (`onOffer`, `choose`, `decline`, `open`), `PortalChooser` (focus-trapped modal, Escape declines, oldest first, a newer offer for the same token replaces), editor `PortalTargetFields` shared with the single-target editor, `portal-use.ts` for "Use portal". The chooser pick sends the option index.

## Placed regions (module placements)

- Modules declare placements (`PlacementDecl`; see `shadowcat-codebase-module-toolchain`). `scene::placed_regions` stamps `PLACEMENT_EXPIRES_AT_KEY` into `system.placement`; `due_placement_regions` lists what is overdue. `Room::expire_due_placements` runs from `spawn_placement_expiry_sweep` (every second over `RoomRegistry::live_rooms`, started in `http::serve_with`, ends at shutdown) under the `ModulePlacement` origin. The stamp persists, so a restart removes an overdue region on the first sweep after its room exists.
- Range: `check_caster_range` measures euclidean span from the caster to the area's bounding-box centre in cells, inclusive; `PlaceEffectError::OutOfRange` is a uniform refusal for a non-GM and a descriptive one for a GM. A declared range makes a non-GM name an owned caster even for `who: player`; a GM with no caster is unlimited.

## Template to region conversion

A template stays a drawing; converting is a GM client action, not a server unification. `scene-docs` `templateToRegionShape` (a result type whose failures are a zero-width line and an unknown shape) and `buildRegionFromTemplate` create a region (terrain cost 1, no effects copied) and delete the template with its pre-image in one batch; `ToolController.convertTemplateToRegion` drives it and `ToolRail` shows "Make this a region" only with both create-region and delete capabilities. The tessellation lives in `@shadowcat/core` geometry and `render` re-exports it, so both sides draw identical outlines.

## Scene bounds padding

`SceneEngine.padding` (cells, bounded by `MAX_SCENE_PADDING_CELLS`, out-of-range or non-finite rejected at validate) widens `SceneBounds {cells, padding_cells}` from `grid_shape`; `sanitize_padding_cells` is the one fallback rule and `world_extent` adds the margin (square: padding times the cell; hex: padding times sqrt(3) x size on x and 1.5 x size on y). A degenerate extent is still refused. The navmesh cache key does not include padding: a scene update clears the cache, and a test pins that. Client twin: `resolvePadding` mirrors `sanitize_padding_cells`; the GM-only authored-bounds outline is `RenderEngine.setAuthoredBounds` -> `Grid.authoredOutline` -> `DisplayBackend.drawBoundsOutline`, and a new `DisplayBackend` member needs every implementation: `PixiBackend`, the mock backend, the dirty-tracking wrapper and the Stage test fake.

## Session pause on the scene tools

`resolveSessionPause` / `sessionFreezes` (spectators are always frozen) feed `ToolContext.movesFrozen`, which makes the move commits (`commitRoute` and the ToolRail drag commit) refuse while select, measure, doors and emotes keep working. `SessionPausedError` comes from a `paused` move or combat error.
